# ADR-0018: Name ADRs by number alone so git blocks duplicate numbers

- Date: 2026-10-20
- Status: accepted
- Supersedes: none (refines the `NNNN-title.md` naming from ADR-0003)
- Superseded by: none

## Context
`decide` picks "highest number in `decisions/` + 1". On a team, two branches cut from the same
main both pick 0018 and write `0018-use-redis.md` and `0018-drop-sqlite.md`. The paths differ, so
git merges both without a word and main ends up with two ADR-0018s. A friend testing orient on a
team hit this, and other ADR repos have too.

## Decision
Name each ADR by its number alone: `decisions/0018.md`. The title stays as the first line
(`# ADR-0018: Drop SQLite`). Two branches that pick the same number now both add the same path
with different content, which is a git add/add conflict. GitHub, GitLab and Bitbucket refuse to
merge a conflicting PR, and they compute that against the current base, so whoever merges second
is blocked until they renumber. `decide` carries a short note on the fix: keep the base branch's
file, save yours as the next free number, fix its heading and references, commit.

Verified in throwaway repos: merge, `merge --squash`, rebase, cherry-pick, a PR from a fork, and
`git merge-tree` (the server-side mergeability check) all stop with `CONFLICT (add/add)`;
different numbers merge cleanly.

`decide` still counts older `NNNN-title.md` files when picking the next number, so repos that
adopted orient before this keep numbering correctly. Numbers are never reused.

## Why this over the alternatives
- **Script + required CI check** — works, but a passed check goes stale when main moves. Closing
  that needs GitHub's "require branches to be up to date" (every merge forces every open PR to
  update and re-run) or a merge queue (org or Enterprise plans only).
- **CI job that re-checks open PRs when main changes** — narrows the stale window but cannot close
  it, needs `pull_request_target` for forks, API paging and rate-limit handling. GitHub-only code to
  maintain for a cosmetic problem.
- **A lock file per number (`.num/0018`) beside slugged names** — keeps readable names, but the lock
  can drift from its ADR: a conflict can be "resolved" on the lock while both ADRs survive.
- **Date-based names** — no clash, but order follows branch date not merge date, and IDs are long.
- **Bot assigns the number at merge** — truly clash-free, but needs a bot with push rights to main
  and leaves drafts unnumbered during review.

## Trade-offs accepted
- **Filenames no longer say what the decision is.** Titles are one `grep -h '^# ADR'` away, and
  searching file contents finds decisions better than filenames did.
- **Not enforcement.** A direct push to main, a force push, or a `merge=ours` merge driver can still
  land a duplicate, and `git merge -X ours`/`-X theirs` auto-resolves the conflict by silently
  dropping one decision. Normal PR merges on any host are covered.
- **Only works once the whole team is on 0.1.8+.** A teammate on an older orient still writes
  `0018-title.md`, which doesn't collide with `0018.md`, so the old silent duplicate comes back
  until everyone updates. Each person's plugin updates on its own schedule.
- **A conflict can be resolved wrongly** (keeping the wrong file, merging the two bodies). The
  conflict makes the clash visible; the fix is still a human or agent step.
- **Byte-identical files merge silently.** Real ADRs differ (title, date, reasoning); only empty
  drafts could match.
- **One-time rename** of this repo's 17 ADRs. Done now while orient has few users.

## Consequences
- No CI, script, hook, setting or network call is needed to stop duplicate numbers.
- `decide` and `init` on all three ports write `NNNN.md`.
- A team member who clashes sees an ordinary merge conflict and fixes it in about a minute.
