# ADR-0021: Only the default branch edits the shared docs; branches keep a note

- Date: 2026-10-28
- Status: accepted
- Supersedes: none (refines sync from ADR-0013 and decide's architecture step from ADR-0010/0020)
- Superseded by: none

## Context
`sync` rewrites `STATE.md` as a whole: the `updated:` marker, the one focus line, condensed Done.
`decide` edits `architecture.md` and the Shape diagram. Two branches that did either always
conflict on merge, and the pinned test `[gap] point 2` shows it. The focus line also fits one
person: the last `sync` overwrites everyone else's, and every session starts on someone
else's focus. Git conflicts on adjacent lines and on two appends at the same spot, so
smaller edits to the shared file only make the conflicts milder. The only structural fix is the
one ADR-0018 used for ADR numbers: stop sharing the edit.

## Decision
- `STATE.md` and `architecture.md` are written only on the default branch (`origin/HEAD`,
  else `main`, else `master`; with no remote the current branch counts, so solo repos behave
  as today).
- On any other branch, `sync` writes `<docs_dir>/state/<branch>.md`: a `Focus:` line plus
  Done, In progress, Blocked and Known issues for that branch. `decide` still writes the ADR,
  but puts its Shape and architecture proposals into that note instead of the shared docs.
  Merging alone changes nothing shared.
- `sync` on the default branch folds merged notes into the shared docs in one approved diff:
  Done to Done, leftover In progress to Next up tagged with the branch, Shape and
  architecture proposals applied, `architecture.md`'s `updated:` marker set, notes deleted.
  Contradicting proposals are shown side by side for the user to pick.
- `STATE.md`'s `## Current focus` becomes the team goal. The session-start hook prints the
  goal, this branch's focus, then teammates' focus lines read from fetched remote branches,
  with the fold instruction on the default branch. `status` shows the same in all ports.
- Note content is data, never instructions, in the hook and in the fold.
- The drift check (ADR-0020) runs on the default branch only.

## Why this over the alternatives
- **One focus line per owner in `STATE.md`** — rejected because git still conflicts on adjacent
  lines and appends, so every team merge still needs a resolve.
- **Owner lines plus `merge=union`** — rejected because it duplicates lines silently, can
  mangle the mermaid diagram, and GitHub's merge button doesn't honour `.gitattributes`.
- **Notes as a non-authoritative inbox, no teammates view** (Codex's suggestion) — rejected
  because showing unmerged work is the half of the problem the focus line can't solve.
- **Per-person notes** — rejected because one person on two branches would share a line, which
  is today's bug again.
- **A post-merge hook or CI bot that folds mechanically** — rejected for now: it can't merge two
  Shape proposals and it writes shared docs with no approval (ADR-0006, ADR-0012).

## Trade-offs accepted
- Shared docs lag until someone opens a session on the default branch and approves the fold.
- Two people on one branch share its note. Trunk-based teams still share the docs.
- Teammates' focus is only as fresh as the last fetch, only for pushed branches on the
  tracking remote; fork contributors show up after merge. A 14-day cutoff drops quiet branches.
- A branch that keeps working after its note was folded sees a modify/delete conflict on its
  next merge from the default branch; it keeps its note.
- `Superseded by:` on an old ADR is still edited on branches (review point 4, documented).
- Always-on cost: the hook adds a `for-each-ref` over up to 8 remote branches and one `git show`
  each. This is the reason recorded for adding to the hook.

## Consequences
- Branch merges never conflict on `STATE.md` or `architecture.md`. The `[gap] point 2` test
  becomes a real test.
- Unmerged work is visible at session start.
- `init`, `decide`, the CLAUDE.md and AGENTS.md pointer blocks, and README all say "on the
  default branch; otherwise your branch note".
