# ADR-0020: Warn when an ADR is newer than architecture.md

- Date: 2026-10-21
- Status: accepted
- Supersedes: none (refines decide's architecture step from ADR-0010)
- Superseded by: none

## Context
`architecture.md` in this repo went stale for two months: four structural ADRs (0009, 0014,
0016, 0019) landed without touching it. Only `decide`'s architecture step updates it, and those
ADRs were written directly as plan steps, without `decide`. This repo's `CLAUDE.md` block was
older than the template and said "record a decision as an ADR" without naming `decide`. Nothing
checked for drift afterwards: `sync` and `status` look only at `STATE.md`. A live test showed the
step itself works: a Postgres → MongoDB ADR through `decide` rewrote every affected line and the
Shape diagram once approved.

## Decision
- `decide` sets `architecture.md`'s `updated:` marker to today on **every** ADR, structural or
  not, as part of the approved ADR write. The marker now means "architecture checked through this date".
- The Claude Code session-start hook prints one line when any ADR's `- Date:` is newer than that
  marker, which means an ADR was written without `decide`. It is silent otherwise, and silent when
  the file or the marker is missing.
- `sync`, in all three ports, runs the same check and offers to update `architecture.md`. This is
  the path for opencode and Codex, which have no session hook.

## Why this over the alternatives
- **Compare file modification times**: git doesn't preserve mtimes, so every clone would look fresh.
- **Count ADRs instead of dates** ("checked through ADR-0019"): needs a new marker format in
  every repo; the date marker already exists in the template.
- **Make the hook update architecture.md**: deciding what changed structurally needs judgement,
  so it stays a model step with approval.

## Trade-offs accepted
- **Always-on cost**: one `sed` and one `awk` over the ADR files per session, with no output
  normally. This is the reason recorded for adding to the hook.
- **Day granularity**: an ADR written without `decide` on the same day as the last marker update
  goes unnoticed.
- **A non-structural ADR written by hand** also triggers the warning until someone sets the marker.
  That's intended: the marker records that someone looked.

## Consequences
- Drift becomes visible on the next session (Claude Code) or the next `sync` (all agents).
- Repos without an `updated:` marker in `architecture.md` get no warning until one is added.
