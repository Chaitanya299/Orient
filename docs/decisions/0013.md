# ADR-0013: STATE.md carries a high-level shape diagram (mermaid)

- Date: 2026-08-25
- Status: accepted
- Supersedes: none
- Superseded by: none

## Context
"Where am I?" should include what the system looks like, not just a list of what's done and
blocked. `STATE.md` answered status in prose; a new engineer still had to assemble the shape
of the system in their head from `architecture.md`'s headed lists.

## Decision
`STATE.md` gets a `## Shape` section holding a mermaid `flowchart` — the major components
(6 nodes max) and how they connect, generated by `init` from the repo survey and updated by
`decide` when a decision changes structure, via the same preview-and-approve path as
`architecture.md`. It sits directly after `## Current focus` so the session-start hook,
which prints only the focus block, never pays for it.

## Why this over the alternatives
Mermaid over ASCII boxes: it renders as a real diagram on GitHub and in Claude, degrades to
readable text elsewhere, and diffs cleanly — ASCII is painful for the model to edit and its
diffs are noise. Mermaid over an indented tree: the tree adds nothing `architecture.md`'s
lists don't already give. Putting the diagram in `architecture.md` instead was rejected to
avoid two drifting copies; `STATE.md` is where you look first, so the shape belongs there.

## Trade-offs accepted
A diagram in a volatile file (rewritten by `sync`) can drift and start lying. Mitigated by
keeping it to 6 nodes so it rarely changes, having `decide` maintain it at the moment
structure changes, and telling `sync` to preserve it (its cap rose 60 → 70 lines to fit).

## Consequences
Orientation is now visual at a glance. The diagram is a maintained artifact, not a
write-once picture, because the one command that changes structure also updates it.
