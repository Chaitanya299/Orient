# ADR-0019: Rename old ADR files automatically on update

- Date: 2026-10-21
- Status: accepted
- Supersedes: none (refines the number-only naming from ADR-0018)
- Superseded by: none

## Context
ADR-0018 switched new ADRs to `decisions/NNNN.md`. Repos set up before 0.1.8 still hold
`NNNN-title.md` files. They number correctly, but stay inconsistent until someone renames them
by hand. The two update paths differ. `npx @chaitanya299/orient@latest` runs inside the repo,
but a Claude Code plugin update is global and never touches any repo. So for Claude Code users,
nothing that runs at update time can see a repo's files.

## Decision
One POSIX script, `plugins/orient/scripts/migrate-adrs.sh`, renames each `NNNN-title.md` to
`NNNN.md` (with `git mv` when tracked) and rewrites links to the old filenames in the repo's
markdown. It runs automatically from both update paths: the Claude Code session-start hook, and
the npm installer on a local opencode/Codex install. Guards:
- Only in orient repos: `<docs>/STATE.md` exists and `CLAUDE.md` or `AGENTS.md` carries the
  `ORIENT:START` marker. adr-tools and similar repos use the same names and are never touched.
- Never while a merge, rebase, cherry-pick or revert is in progress, or with unmerged ADR files.
- A file whose number is already taken by `NNNN.md` is left in place and reported.
- Renames are staged, never committed; the user reviews them with `git status`.
- Idempotent, and silent when there is nothing to do. It always exits 0.

## Why this over the alternatives
- **`init` offers the rename** — keeps "nothing writes without a yes" intact, but depends on the
  user re-running `init`. The user chose fully automatic.
- **Skip the migration** — 0.1.8 already numbers around old names, so nothing breaks. Rejected:
  mixed naming is confusing, and leaves `NNNN-title.md` files that don't get the add/add protection.

## Trade-offs accepted
- **An exception to "nothing writes silently".** It is narrow: deterministic renames and link-path
  rewrites only, no content changes, uncommitted. README and SECURITY.md state it.
- **Always-on cost.** The session-start hook now globs `decisions/` every session. That's one
  shell glob with no output in the normal case, so it adds no tokens. It is justified because it is
  the only automatic path for Claude Code users.
- **Link rewriting is textual.** It replaces exact old filenames in `*.md` files. A filename
  mentioned in a non-markdown file is left alone.
- **Windows without `sh`**: the installer prints that it skipped; the hook already needs `sh`.

## Consequences
- After updating, an old repo converges to number-only names on the next session or install.
- The append-only rule still holds for ADR bodies; only the filename and link text change.
